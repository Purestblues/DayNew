04 · 四大原生体验实现对比

为什么原生 Compose 在关键边界上显著省心

原生能力边界 Kotlin + Jetpack Compose（方案 A） KMP + CMP（方案 B） Flutter（方案 C）
桌面小组件
AppWidget		 Jetpack Glance 用类 Compose Kotlin 直写；点勾选直接复用 :core-sync 仓储与 CompletionLog，零跨运行时同步问题。 androidMain 写 Glance，共用 commonMain 仓储，但多模块 Gradle 构建复杂度上升。 无法直接在 Glance 跑 Dart；需维护一套 Kotlin XML/Glance + SharedPreferences 回传通道，易出现状态延迟。
精确闹钟提醒
pre15/pre5/start/end		 AlarmManager.setExactAndAllowWhileIdle + BroadcastReceiver；系统唤醒时仅加载轻量 JVM 类，触发通知栏「完成 / 延后」。 与原生 A 相似，实现位于 androidMain，无功能缺失。 闹钟响起时若在通知栏点「完成」并触发同步，要么拉起 Dart Engine，要么在 Kotlin 里重写一遍业务写盘与同步。
系统分享收纳
ACTION_SEND		 独立透明 BottomSheetActivity，冷启动 < 150ms 弹出，选中文字一键扔入「今天」或「未来事项」。 原生体验，仅多一层 KMP 依赖包装。 单独 Activity 拉起 FlutterEngine 易见短暂白屏或显存开销。
Nord Frost UI
与 120Hz 手感		 直接套用 android-compose.md（shadowElevation=0.dp 列表零阴影 + 1.dp 描边 + 90/150/225ms 动效），贴合系统返回手势。 Android 上由 CMP 编译为 Jetpack Compose，多了一层 Skia/资源适配考量。 帧率同样稳定 120Hz，但中文系统字体渲染、阴影/滚动物理及预测性返回偶有非原生割裂感。
